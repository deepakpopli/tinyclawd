# AGENTS.md

notes for anyone (or any coding agent) working in this repo.

## layout

```
firmware/     esp-idf app for the ESP32-C3 (pet engine, display, touch, usb link)
bridge/       laptop side: claude code status line + hooks -> usb serial -> pet
animations/   eyes.py = reference design of every animation (1-bit 128x64), gifs/ = previews
hardware/     openscad designs, fit/print checks, build.sh, print/ = files to print
```

## hardware

| part | detail |
|---|---|
| mcu | ESP32-C3 Super Mini, 4 MB flash, USB-Serial-JTAG on /dev/ttyACM0 |
| display | SH1106 128x64, I2C 0x3C, SDA GPIO20, SCL GPIO21, column offset 2 (132-wide ram) |
| touch | TTP223 on GPIO1, active high |
| other | no buzzer, no battery, usb-c power. onboard antenna is weak |

## firmware

esp-idf v5.4.x, C++.

```bash
. ~/esp/esp-idf/export.sh
idf.py -C firmware build
idf.py -C firmware -p /dev/ttyACM0 flash monitor
```

keep the pet engine (state + animations) free of esp-idf headers so it also builds on the desktop
simulator and can be tested without the board. both builds use C++17 (gnu++2b clashes with our
`lerp`).

```
firmware/components/pet/   portable engine
  include/canvas.h         1-bit 128x64 framebuffer in SH1106 page layout, PIL style primitives
  include/face.h           Clawd eyes (shapes, blink, small props)
  include/clawd.h          mini Clawd block sprite + the 13 step turn
  include/anim.h           Anim = {name, draw(canvas, t_ms, ctx), ms, flags}
  src/anims_*.cpp          animations by group, each file ends with ANIM_LIST(...)
  src/brain.cpp            the director: modes, pools, cooldowns, transitions
  src/proto.cpp            line protocol parser (firmware/PROTOCOL.md)
  src/fonts.cpp            generated by firmware/tools/gen_fonts.py
firmware/main/             board side: sh1106, touch, usb link, render task
firmware/sim/              desktop build: ./sim list | anim <name> | all | script <file> | soak [h]
```

animation rules: a draw function is a pure function of `t` and `ctx` (no static state), so it
is smooth at any fps. use `ctx.seed` for variations. flags: `LOOP` (draw wraps t), `CALM_IN` /
`CALM_OUT` (first / last frame is the plain face, the brain cuts without a transition), `SCENE`
(full screen scene, the brain dissolves in and out).

brain: a base loop per mode (idle, thinking, tool, waiting, asleep) plus one-shots from weighted
pools (`Pick {name, weight, cooldown_s}`) that never repeat the last two. tool names map to
pools in `TOOLS`. `tune fast` over serial shortens the idle timings for testing.

## bridge

python 3.8+, standard library only, plus pyserial for the daemon. hooks must stay fast, silent
and exit 0 even with no daemon (only `screen` prints, and only for `/clawd`).

```bash
python3 bridge/test_bridge.py   # hooks, daemon state, music, typing, eq, a daemon on a pty
python3 bridge/test_setup.py    # setup.py and install_hooks.py in a throwaway HOME
```

never try setup.py against the real `~/.claude` or `~/.config/systemd`: use a temp `HOME` and a
fake `systemctl` on `PATH`, like `test_setup.py` does. `install.sh` at the top is the one line
installer the site serves.

## animations

`animations/eyes.py` is the spec. every animation is plain shapes (rects, lines, small glyphs) on a
1-bit 128x64 canvas, so it ports 1:1 to C++. Clawd's eyes are solid slits, no pupils.
`animations/clawd_sprite.py` holds the mini Clawd block art and its 360 turn, taken from the
Claude Code banner.

## hardware files

`hardware/build.sh` rebuilds everything and runs the checks (`check_fit.py`, `check_stands.py`).
any change to a housing must keep `check_fit.py` passing: the inside has to stay identical to the
original Mochi frame. 3mf parts are mapped to AMS slots in `print_3mf.py`.
